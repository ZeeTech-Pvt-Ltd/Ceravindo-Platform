# Ceravindo — project notes

The standing brief in `~/.claude/CLAUDE.md` applies in full. This file records

## Stack

**Next.js 16 App Router**, static export. This project is the Next.js
exception to the "React + Vite" default in the global brief, and follows
`Ai-Nobiloption` (migrated 2026-10-20).

```
app/
  layout.jsx            root shell: fonts, metadata, header/footer, providers, GA
  globals.css           the whole design system, one file
  page.jsx              home, with the section list
  <route>/page.jsx      one directory per route
  not-found.jsx         becomes 404.html
src/
  components/           all UI
  data/                 site, content, countries, legal, market, seo
  hooks/                useReveal
  lib/                  metadata mapping, phone helpers, lead submission
source-images/          originals for the supplied artwork (gitignored)
```

`next.config.mjs` sets `output: 'export'` and `trailingSlash: false`. Routes
build to `out/<route>.html`, so canonical URLs stay slash-free and `/about` is
served straight from `about.html`. `out/404.html` gives an unknown path a real
404 status.

Build with `npm run build`. Output is `out/`, not `dist/`.

## Rules that are easy to break here

- **`'use client'` is required** on anything with a hook: `Header`, `Faq`,
  `HeroVisual`, `TradingDashboard`, `ThankYou`, `LegalModal`, `PhoneField`,
  `RegistrationForm`, plus `RevealProvider` and `ScrollHandler`.
- **Fonts go through `next/font/local`**, not `next/font/google`. The WOFF2
  files are in `public/fonts` and the privacy policy says they are served from
  this domain; switching to Google Fonts makes that sentence false.
- **The reveal hide rule is gated on `@media (scripting: enabled)`**, never on
  a class added to `<html>`. Next hydrates `<html>`'s attributes, so an inline
  script that sets a class there causes a hydration mismatch. A bare
  `.reveal { opacity: 0 }` would blank the page for a crawler.
- **Metadata comes from `src/lib/metadata.js`**, which maps `src/data/seo.js`
  onto Next's Metadata API. Do not hand-write head tags in a page.
- **Noindex routes carry no canonical.** `pageMetadata()` already omits it when
  `canonical` is null. `app/not-found.jsx` also drops `robots`, because Next
  adds its own and two tags end up in the HTML.
- **Analytics and Search Console live in `app/layout.jsx`**, not in an
  `index.html`. The CSP in `vercel.json` allowlists both Google hosts; without
  that entry the tag is blocked in production while local checks pass.
- **`vercel.json` has no rewrites.** Static export emits one file per route, so
  a rewrite to `/about/index.html` would 404. Redirects and headers only.
- **`AGENTS.md` at the repo root is generated by `next dev`.** Removing it only
  re-creates it.

## Verifying

Several Zeetech projects share this machine, so more than one dev server is
often listening. Confirm the server is serving *this* site before testing:

```bash
curl -s http://localhost:<port>/ | grep -o '<title>[^<]*'
```

It must say "Ceravindo". A port serving another project returns 200 and looks
fine, which is how an audit ends up measuring the wrong site.

```bash
npm run build
node .arttmp/serve-dist.mjs 4180        # serves out/, not dist/
node .arttmp/verify-ssg.mjs             # …then the other seven suites
```

`serve-dist.mjs` maps `/about` to `about.html`, serves `_next/` from disk, and
returns `404.html` with a real 404 status for anything unknown. Do not replace
it with `next start` - that does not exist with `output: 'export'`.
